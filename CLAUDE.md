# find-trends

A **no-backend** React SPA that reads static CSVs shipped with the app and charts daily/
weekly/monthly/yearly trends across cities and markets, alongside a curated feed of world
events. Hosted on GitHub Pages. Everything runs in the browser — no server, no API keys.

**End goal:** the user uploads their shop's **sales** file and correlates it against
weather + economic factors to find trends. Sales **upload + bottom-of-chart bars + a
selected-period stats card** now ship (see "Sales data" below); richer **comparison views**
(scatter, correlation ranking) are the remaining pending work.

## Stack & hosting

- Vite + React + TypeScript, Tailwind CSS v4 (`@tailwindcss/vite`), Recharts v3, PapaParse. **SheetJS (`xlsx`)** parses uploaded sales workbooks — pinned to the CDN tarball (`https://cdn.sheetjs.com/xlsx-0.20.3/…`, NOT the npm registry build, which carries a known advisory) and **lazy-imported** inside `parseSalesFile` so its ~160 KB gzip chunk only ships on upload.
- Live: https://heraphim.github.io/find-trends/ — repo `heraphim/find-trends`.
- Deploy: push to `main` → `.github/workflows/deploy.yml` builds and publishes to Pages. It also redeploys after the daily data refresh (chained via `workflow_run`, since a `GITHUB_TOKEN` push can't trigger it directly).
- `vite.config.ts` sets `base: '/find-trends/'` and injects `__COMMIT_DATE__` / `__BUILD_DATE__` (shown in the floating pill; frozen at dev-server start in `npm run dev`).

## Data source

Static CSVs in `public/data/`, served from the app's own origin (no external calls at runtime).
- Tab discovery: fetch the ordered manifest `public/data/tabs.json` (`lib/workbook.ts`).
- Per-tab data: `public/data/<tab>.csv`, lazy-loaded via `${BASE_URL}data/<tab>.csv`, parsed by `lib/sheet.ts`. File name = tab name (`brasov-weather.csv`, `euro.csv`, …).
- **Provenance:** each CSV is generated by a Python script in `scripts/getting-data/` — `days_generate.py`→`days`, `weather_generate.py`→`weather_brasov`/`weather_sibiu`, `eurron_generate.py`→`eurron`, `commodities_generate.py`→`commodities`; `_generate_all.py` runs them all. All series start 2020-01-01 and are forward-filled to every calendar day (weekends/holidays carry the last value).
- **Refresh:** `.github/workflows/refresh-data.yml` runs the generators on a **daily midnight cron only** (never on push), copies the output into `public/data/` renamed to tab names, and commits any changes back to `main`. To refresh manually, run `python scripts/getting-data/_generate_all.py` locally (writes to `scripts/getting-data/`, gitignored) or trigger the workflow from the Actions tab.

### Events data (curated, AI-assisted — separate from the trend tabs)

`public/data/events/` holds curated event datasets for the future event-overlay feature. **Not in `tabs.json`** — they're date *ranges*, not a daily `date` series, so the app doesn't load them as trend tabs. Unified schema: `Start Date,End Date,Event Name,Event Type,Impact Category,Positive or Negative,Importance (1-100),Description` (ISO `YYYY-MM-DD` dates). Files: `brasov_events.csv`, `sibiu_events.csv`, `romania_events.csv`, `global_events.csv`.
- **Generation:** `.github/workflows/generate-events.yml` — **manual (`workflow_dispatch`) only**. Runs Claude Code (`claude -p`, prompt in `.github/prompts/generate-events.md`) on the user's **Claude subscription** via the `CLAUDE_CODE_OAUTH_TOKEN` secret (from `claude setup-token`; not API-key billing), then opens a **PR for human review** via `peter-evans/create-pull-request`. Pinned to **`--model sonnet`** (Opus was ~$9.71-equivalent/run — overkill for data entry). The Claude step runs with `--output-format json`; a follow-up step parses the token usage + `total_cost_usd` into a **cost report** shown in the PR body and the Actions run summary. The prompt is **append-only** — it must never modify or delete an existing row (the one-time backfill of empty columns was done manually via the first PR); it only adds brand-new events. Deliberately not scheduled and never auto-committed: AI output is non-deterministic and can hallucinate, so a human gates every change to this correlation-input data. Setup: the `CLAUDE_CODE_OAUTH_TOKEN` secret (paste with no stray whitespace — the workflow strips it defensively, since a newline in the token is rejected as an invalid HTTP header) + the repo's "Allow GitHub Actions to create and approve pull requests" setting.
- **Tabs:** `days` (per-day reference/filters — first sheet), `brasov-weather`, `sibiu-weather`, `commodities`, `euro`.
- **Naming rule:** `xxx-yyy` → city `xxx` (an include-checkbox) + category `yyy`; a no-hyphen sheet is a **global** category shown for every city. `days`/`date` is the filter sheet, not a category.
- **Column rule:** numeric col = plottable **metric**; non-numeric (text/TRUE-FALSE) = **event**/day-classifier. `weather_code` is force-classified as an event.
- **Columns per tab (after the getting-data refresh):**
  - weather: raw (`temp_*`, `apparent_temp_max/min`, `precipitation`, `rain`, `snowfall`, `wind_max`, `wind_mean`, `weather_code`, `is_forecast`), **v1 scores** (`ideal_temp`, `temp_score`, `rain_score`, `wind_score`, `sunshine_percentage`, `snow_bonus`, `nice_day_score`, `nice_day_label`, `heavy_rain`, `sunny_day`, `outdoor_score`), and **v2 scores** (`comfort_score_v2`, `rain_score_v2`, `wind_score_v2`, `hazard_factor`, `nice_day_score_v2`, `nice_day_label_v2`, `outdoor_score_v2`). Weather now includes a **7-day forecast** (`is_forecast=TRUE`).
  - euro (FX): `eur_ron` (BNR official rate), `change_pct`, `big_move` (event flag).
  - commodities: `<name>_close` + `<name>_change_pct` for Brent, EuroGas (Dutch TTF, replaced Henry Hub), Wheat, Corn, Gold, Copper.
  - days filters: `is_weekend`, `season`, `is_holiday` (RO public holidays). `is_weekday`/`weekday` are excluded as redundant.

### Column display registry (do this for EVERY new column)

Presentation — a column's **display name** and whether it **shows in the app** — lives in the `lib/metricMeta.ts` registry, **never** encoded into CSV headers. The getting-data generators own the raw column names (they double as registry keys and API field names); they must stay machine-clean. So whenever a generator adds/renames a plottable/event column, add a matching registry entry in the **same change**:

- Give it a human `label` and a `tier`: **`primary`** (shown by default in the category dropdown), **`advanced`** (behind the dropdown's "Show advanced" toggle), or **`hidden`** (pure derivation/internal — e.g. `ideal_temp`, `snow_bonus`, `is_forecast`; never surfaced). Metrics go in the `WEATHER`/commodity/FX branches of `metricMeta()`; non-numeric event/day-classifier columns go in the `EVENTS` map (label + tier only).
- Rule of thumb: v2 scores are `primary`, v1 scores `advanced`; raw components (`apparent_temp_*`, `rain`, `wind_mean`, `*_change_pct`) `advanced`; headline series (`temp_mean`, `precipitation`, `*_close`, `eur_ron`, `nice_day_score_v2`) `primary`.
- Unregistered columns fall back to `advanced` + raw-key label and log a dev-only `console.warn` — so nothing silently vanishes, but the warning is the signal to add an entry. The `days` sheet is exempt (it feeds `DayFilters`, not chart metrics, and has its own labelling there).

## App architecture

`Dashboard.tsx` owns almost all state and composes everything. Key pieces:

- `lib/workbook.ts` — discover tabs, build the city/category model.
- `lib/sheet.ts` — fetch + parse a tab into `{rows, columns}`; classify metric vs event.
- `lib/data.ts` — types, date parsing, bucketing/aggregation (`aggregateMerged`), % rebasing, Pearson correlation, day-count-per-bucket, `bucketToRange` (clicked point → period), `bucketRow`/`mergeRowsByT` (shared row builder + union-by-`t`, used to merge sales bars onto the line time axis).
- `lib/sales.ts` — uploaded **sales** datasets: `parseSalesFile` (lazy `xlsx`; row 3 titles / row 4+ data / col G date / col I amount; reads **raw serials**, not `cellDates`, and keeps blank rows so the fixed layout stays aligned to absolute sheet rows), the city parsed from a `"City - …"` filename prefix, per-bucket **sum** + the two change series (`chg_prev`, `chg_avg5` — computed on the already-filtered buckets), and `salesStatsInRange` for the day card. Persists under `ft.sales` / `ft.salesSel`.
- `lib/metricMeta.ts` — the **column display registry**: per-column display `label`, `unit`, roll-up, chart `group`, and `tier` (primary/advanced/hidden — see the rule above). `metricMeta()` covers plottable metrics (weather raw + v1/v2 scores share one "Scores" chart, `hazard_factor` ×, `eur_ron` RON + `change_pct` %, commodity `close` + `change_pct`); the `EVENTS` map covers non-numeric event columns; `columnMeta()` returns `{label, tier}` for any column.
- `lib/dayFilters.ts` — parse the `days` sheet into filter dimensions (weekend/season/holiday…) + date→attributes map; excludes the redundant `is_weekday` name column.
- `lib/dateRange.ts` — range math + option lists for the Range picker.
- `lib/events.ts` — Wikipedia events + heuristic importance scoring (see below).
- `lib/eventsData.ts` — loads the curated event CSVs in `public/data/events/` (rich schema, ISO dates); `filesForSelection` resolves the `local` source to the included cities' files; `eventTier` maps importance → major/notable/minor; `eventsInRange` filters + sorts.
- `lib/chartColors.ts` — validated colorblind-safe palette (light/dark).
- `hooks/useTheme.tsx` — theme context; **dark is default**; no-flash script in `index.html`.
- `hooks/usePersistedState.ts` — localStorage-backed state; ALL config persists under `ft.*` keys. **The time window is the single source of truth** and lives in `ft.timeHistory` (see "Time source of truth" below) — persisted so it survives reload and can be shared. Also re-reads its key on the `FT_SYNC_EVENT` custom event, so an imported config snaps the whole app without a reload.

### Time source of truth — Range + Time unit (`ft.timeHistory`)

Range (the date window) and Time unit (granularity) are the app's central axis of truth — every view derives from them and every other control feeds into them. They live **together** in `Dashboard.tsx` as a **history stack** of `{range, gran}` snapshots (`ft.timeHistory`, newest = current):
- **Every range/unit change pushes** a snapshot via `commitTime` — the picker's mode/sub-selection, a granularity toggle, **drag-zoom** (`zoomTo`) or the **Zoom ＋/－ buttons** (`zoomIn`/`zoomOut` — zoom is *not* a separate concept, it just commits a new range), `jumpToDay`, and Next/Prev. Pushes are **deduped** (no repeat snapshot in the stack — an equal one is moved to the top) and **capped at 10** (oldest dropped).
- **Back** (`back`, shown when depth > 1) pops the top; there is no separate zoom stack.
- **Zoom** (`zoomRange` + `zoomInSnap`/`zoomOutSnap`): scales the window by a factor about an **anchor fraction** (0 = start, 0.5 = centre, 1 = end), snapped to whole days. **Zoom-in drills through units:** it shrinks the window until only **one unit fills the screen** (snapping to that unit's full span — a straddling window that dips under the unit's `LEVEL_MIN_DAYS` snaps to the whole unit at the anchor), then the **next zoom-in switches to the finer unit** (all → year → month → week → day) keeping the window; the floor is a single day at day units. Zoom-out grows the window, keeping the unit. **Bounds follow the data** (`zoomBounds`): sales tx extent when sales are plotted, else the shown series, else the day-sheet `bounds` — so zooming/panning can't run past the sales data. The ＋/－ **buttons** anchor at the **centre**; **gestures** (`hooks/useChartGestures.ts`, native non-passive listeners on the chart wrapper) anchor **under the pointer**: **wheel scroll** and **two-finger pinch** (anchored at the pinch midpoint) both zoom; a rapid burst **coalesces** into one history entry (`GESTURE_COALESCE_MS`, `commitTime`'s `{replace}` swaps the top instead of pushing).
- **Pan** (`panRange`): **middle-button drag** = grab-and-drag horizontal pan (drag right → window moves *back* in time), span preserved, clamped to `zoomBounds`; applied to the gesture's base range (captured on the first move via `panBaseRef`) so day-snapping doesn't swallow accumulating sub-day motion, and the whole drag is one history entry. **Left-button** drag stays Recharts' drag-to-zoom — the chart's `onMouseDown` ignores non-left buttons so the middle button never starts a range selection. `MultiTrendChart` takes `onGestureZoom`/`onGesturePan` and the wrapper carries `touch-none`.
- **Granularity clamps to the range's actual span** (`maxLevelForRange`), not to a range *mode* — a single-day range only allows Days, etc.
- **The range snaps to REAL units** (`snapRangeToUnit`, baked into `commitTime` so it covers every path — picker, zoom, pan, next/prev, drill): at week units the start snaps to the nearest **Monday** and the end to the nearest **Sunday**; months → the **1st** to the month's **last day**; years → **Jan 1..Dec 31** (day/all pass through). Start/end round to the *nearest* boundary (ties expand outward); a collapsed result keeps exactly one whole unit. A snapped range may overhang the data by a partial unit, so `canZoomOut` compares at *bucket* level against `zoomBounds`.
- **`rangeMode`** (`ft.rangeMode`) is now just the `DateRangePicker`'s preset-UI state (which sub-control shows); it no longer owns or derives the range.
- **Focus** (`focusedT`, a clicked bucket) defaults to the **whole active range** so the Selected-period card is never empty; it resets to that default on *every* range/unit change (baked into `commitTime`), **except** Next/Prev. **Next/Prev** slide the whole window one unit (drop a unit off the start, add one to the end); if a single bucket is focused they move the focus to the newly-revealed edge in the same commit, otherwise the whole-range view just pages by one unit. The card's ← / → buttons are **always visible** (not gated on a click) and only **disable** at the data's edges (`canPrev`/`canNext`, window-edge vs `dataExtent`).
- `lib/shareConfig.ts` — **share / import the whole dashboard config**. Snapshots the shared `ft.*` keys (via `SHARE_KEYS`) into a compact base64url token; `applyToken` writes them back + fires `FT_SYNC_EVENT`; `applyShareFromUrl` (called in `main.tsx` **before** React mounts) consumes a `?s=<token>` link then strips the param. The uploaded sales **data** (`ft.sales`) is **never** shared; the sales-metric selections (`ft.salesSel`) ride along but are filtered on apply to datasets the recipient has locally. The time window travels as `ft.timeHistory` (the range+granularity history stack, which replaced the old `ft.range`/`ft.zoom`/`ft.gran` keys); `ft.rangeMode` rides along so the picker shows the same preset control. Drives the header `ShareControls` (Copy / Paste / Link).

Layout is a vertical stack: **Cities → CategoryBar → Day-filters row → Sales panel → Sales summary panel → chart → selected-period stats card → curated events panel → Wikipedia events panel**. Components: `CityControls` (city checkboxes + overlap), `CategoryBar` (horizontal dropdowns of metric checkboxes per category **+ an Events entry** with Local/Romania/Global source toggles; replaced the old right-hand `Sidebar`, whose file now only holds the shared `SheetState`/`SidebarCategory` types), `DateRangePicker` (Range: Day/Week/Month/Year/All **presets** — each button/sub-selection *emits* a range to `commitTime`; it no longer owns the range), `GranularityToggle` (Time units, clamped to the active range's span), a **Zoom ＋/－** control (centre-based zoom in/out — see "Time source of truth"), `DayFilters` (own horizontal row), `SalesPanel` (Upload button + one card per uploaded dataset: city, count, span, remove, and Amount/Δ-prev/Δ-avg5 checkboxes — **Amount checked by default**), `SalesSummaryPanel` (under Sales; one card per checked dataset with avg/best/biggest figures, day-anchored figures clickable to jump the range), `MultiTrendChart` (Recharts **`ComposedChart`**; lines on the default axis, **sales bars via `barSeries` on a hidden bottom-band axis**, `barGap={0}` so same-day bars touch and gaps fall only between days; vertical gridlines delimit each time unit when ≤60 buckets **plus always-on top/bottom `Customized` notches at each unit boundary** (thinned when dense) so the day/week/month limits stay visible at any density; with **no line/bar series** the chart still renders from a `bucketSkeleton` time axis (empty y-axis hidden) so an **events-only** selection shows its markers; the category-axis tooltip cursor is a translucent **band** that highlights the hovered unit; hovering a **series legend** entry glows that line/bar and dims the rest, and hovering an **event-legend** entry glows its marker via the `hoveredMarkerKey` prop; click a point → focus events; renders curated events as `ReferenceLine`/`ReferenceArea` markers drawn on top via the `eventMarkers` prop), `DayStatsCard` (**always shown** when ≥1 included city has data — one column per included city; shows the clicked bucket's period, or the **whole active range** when nothing is clicked — total money / purchase count / average / 3 lowest + 3 highest; next to each city name are **glance glyphs** — a nice-day smiley, rain/snow icons, and a 💰 up/down vs that city's average day — whose numeric detail shows on hover; ← / → arrows are **always shown** and step the period one unit — sliding the whole window and moving focus to the revealed edge, or paging the whole-range view — disabled only at the data's edges), `CuratedEventsPanel` (our events, above Wikipedia), `EventsPanel` (Wikipedia), `ShareControls` (header Copy/Paste/Link — see `lib/shareConfig.ts`), `BuildInfo`, `ThemeToggle`.

### Behaviour notes

- Cities are multi-select checkboxes (no tabs). Metric selection is city-agnostic (`category::column`); a checked metric plots for every included city that has it.
- **Overlap** on → all series on one chart; off → one chart per city (+ a "Markets" chart for globals).
- Chart shows **actual values** (Scale toggle also offers **% change** to compare different-magnitude series). All non-sales data **averages**; the total/average radio is reserved for future sales data (sales bars themselves always **total** per bucket, per the user's call).
- Correlation (Pearson r) shown per chart; per-series color pickers; matching-day counts in the total line + tooltip. Sales **amount** series are folded into the correlation set (weather ↔ sales r); the % scale rebases only the lines — sales bars stay in actual units on their own axis.
- **Sales:** a dataset maps to a city via its `"City - …"` filename; with overlap off, its bars ride that city's chart. Bars sit in the lower ~⅓ (hidden padded axis). **Uploading a file for a city that already has a dataset MERGES into it** (concat + re-sort, summary recomputed) rather than adding a second entity — only files with no `"City -"` prefix stay separate; a new dataset checks **Amount only** by default. Day filters + the active range narrow the buckets before the change series are derived. **A dataset only plots (bars + stats) when its city is selected in the Cities row** — otherwise it stays listed in the Sales panel with a "hidden · city not selected / no city in filename" badge. The day card ignores day filters (the user explicitly picked that period) and renders **one column per included city**: that city's total money / purchase count / average / **3 lowest + 3 highest** purchases (checked datasets only); weather now appears only as **hover glyphs** next to the city name (nice-day smiley, rain/snow, and a 💰 comparing the period's mean daily takings to the city's all-time average day). Cities without sales still show as a glyph-only column. The chart's **day tooltip includes the weekday**. Money figures carry a **`RON` suffix** everywhere they're shown (day card, summary panel, sales-bar tooltip).
- **Sales summary panel** (`SalesSummaryPanel`, directly under the Sales panel; shown only when ≥1 dataset is checked): one card per selected dataset with dataset-intrinsic roll-ups — avg per day / weekday / weekend / week / month, plus **best day**, **best day of the other kind**, and **biggest purchase** as clickable figures that jump the chart range to that day. The `SalesSummary` is computed at `parseSalesFile` time (`computeSalesSummary`), persisted on the `SalesDataset`, recomputed on same-city merge, and **lazily backfilled** (versioned via `SALES_SUMMARY_VERSION`) for datasets saved before it shipped.
- **Events panel:** ≤10-day ranges → Wikipedia Current Events daily digest; longer → year-article "Events" (curated majors), filtered to range. Heuristically scored (topic weight + impact keywords + casualties + coverage), tiered major/notable/minor, "Important only" hides minor. Clicking a chart point focuses the panel on that point's period. Recharts v3 `onClick` gives `activeIndex` (NOT v2's `activePayload`). The curated markers drawn on the chart are also **named directly beneath it** by `MarkerLegend` (Dashboard), split into "Event ranges" (shaded bands) and "Events" (single-unit markers), colour-dotted by the marker's colour — a **local** event uses its **city's series colour** (band tinted with transparency on the chart too); Romania/Global use the tier colours. **Overlapping bands hatch**: depth 2 → diagonal lines, 3+ → cross-hatch (sweep-line segments in `EventBands`).

## API gotchas (verified)

- Wikipedia REST "on this day" only has **historic** events (nothing ≥2020) — unusable here.
- **GDELT is CORS-blocked** from the browser (needs a backend) and is article-level, not curated.
- Energy-prices / FRED / Stooq are CORS-blocked; Frankfurter (FX) and World Bank (annual) work but weren't added.
